# Contributing Guidelines

Thank you for contributing to this project.

## 1. Before Contributing

Before making changes:

1. Read the README.md file.
2. Check existing issues.
3. Avoid duplicating existing work.
4. Create an issue if clarification is required.

## 2. Create a Branch

Do not make development changes directly on the main branch.

Create a separate branch for your work.

Recommended branch formats:

feature/<short-description>
bugfix/<short-description>
docs/<short-description>
refactor/<short-description>

Examples:

feature/login-page
bugfix/installation-error
docs/update-readme
refactor/project-structure

## 3. Make Changes

Make small and focused changes.

Follow the existing project structure and coding conventions.

## 4. Test Changes

Before creating a pull request:

- Check that the project works.
- Check modified documentation.
- Check links and file paths.
- Verify that no unnecessary files are included.

## 5. Commit Changes

Use short and meaningful commit messages.

Recommended format:

type: short description

Examples:

docs: update installation guide
docs: improve README
fix: correct installation command
feat: add issue template
chore: organize documentation

## 6. Pull Request

Create a pull request after completing the changes.

The pull request should contain:

- Description of the change
- Related issue
- Testing performed
- Screenshots where appropriate

## 7. Review

Changes should be reviewed before being merged into the main branch.
