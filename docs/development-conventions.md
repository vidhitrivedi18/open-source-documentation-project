# Development Conventions

## Branch Naming Convention

| Branch Type | Format | Example |
|---|---|---|
| Feature | feature/name | feature/login-page |
| Bug Fix | bugfix/name | bugfix/login-error |
| Documentation | docs/name | docs/update-readme |
| Refactoring | refactor/name | refactor/project-structure |

## Branch Rules

1. Use lowercase letters.
2. Use hyphens to separate words.
3. Keep branch names short.
4. Use a branch type prefix.
5. Do not use spaces.
6. Do not directly develop features on main.

## Commit Message Convention

Format:

type: short description

### Commit Types

- feat: New functionality
- fix: Bug correction
- docs: Documentation changes
- refactor: Code restructuring
- test: Testing changes
- chore: Maintenance

### Examples

docs: improve installation guide
docs: add contribution guidelines
feat: add issue template
fix: correct documentation link
chore: organize repository files
